── PASO 8: Composable Vue para permisos ──
Crear usePermissions.ts en resources/js/composables/:

import { usePage } from '@inertiajs/vue3'
import { computed } from 'vue'

export function usePermissions() {
  const page = usePage()
  
  const permissions = computed<string[]>(
    () => (page.props.auth as any).permissions ?? []
  )
  const roles = computed<string[]>(
    () => (page.props.auth as any).roles ?? []
  )

  const can = (permission: string): boolean =>
    permissions.value.includes(permission)

  const hasRole = (role: string): boolean =>
    roles.value.includes(role)

  const canAny = (perms: string[]): boolean =>
    perms.some(p => permissions.value.includes(p))

  return { can, hasRole, canAny, permissions, roles }
}

=============================================================
REGLAS DE NEGOCIO CRÍTICAS
=============================================================
1. super_admin bypassa TODOS los permisos 
   (usar Gate::before en AppServiceProvider)
2. Un usuario solo puede tener UN rol activo 
   (syncRoles, no givePermissionTo directo)
3. client SOLO accede a tickets.view_report 
   donde el documento del ticket coincida con 
   el suyo (validar en Policy, no solo en ruta)
4. Los ApiTokens del módulo uploadImage son 
   completamente independientes de Spatie. 
   NO modificar su lógica de autenticación.
5. EnsureUserIsActive debe rechazar con 403 
   (no redirect a login) si el usuario existe 
   pero está inactivo
6. Los permisos se cachean automáticamente con 
   Spatie. Documentar cómo limpiar el caché 
   cuando se cambie un rol: 
   app()[\Spatie\Permission\PermissionRegistrar::class]
     ->forgetCachedPermissions();
